# Quick Task 260820-sw7: Add habitat (Stanište) field to species profiles

## Goal

Species profiles get a second free-text field, `habitat` ("Stanište"), alongside the
existing `description` ("Opis"). Editable from the species detail view, persisted
locally in SQLite, preserved by every other writer of `species_profiles`.

## Tasks

### Task 1 — Persistence layer (Rust + SQLite)

**Files:**
- `src-tauri/migrations/0023_species_profile_habitat.sql` (new)
- `src-tauri/src/commands/import.rs`
- `src-tauri/src/commands/finds.rs`

**Action:**
- New migration adds `habitat TEXT` to `species_profiles`.
- Register `MIGRATION_0023`, add a `if version < 23 { ... }` guarded block following the
  0020/0022 pattern (pragma_table_info existence check, then `PRAGMA user_version = 23`).
- Add an idempotent repair block for `habitat` mirroring `synonyms`/`other_names`, so
  local DBs whose `user_version` already advanced still get the column.
- `SpeciesProfile` struct gains `habitat: Option<String>`; `get_species_profiles` SELECT
  and row mapping include it; `upsert_species_profile` takes a `habitat` param and
  writes it in the INSERT + `ON CONFLICT DO UPDATE` (plain `excluded.habitat`, matching
  `description`, so the field can be cleared).

**Verify:** `cargo check` in `src-tauri` passes.
**Done:** Column exists, round-trips through the two commands.

### Task 2 — Frontend plumbing

**Files:**
- `src/lib/finds.ts`
- `src/hooks/useFinds.ts`
- `src/tabs/CollectionTab.tsx`, `src/tabs/SpeciesTab.tsx`
- `src/components/finds/CreateFindDialog.tsx`, `src/components/finds/EditFindDialog.tsx`
- `src/components/import/ImportDialog.tsx`

**Action:**
- `SpeciesProfile` TS interface gains `habitat?: string | null`.
- `upsertSpeciesProfile` wrapper takes `habitat` and always sends `habitat ?? null`.
- `useUpsertSpeciesProfile` mutation variables gain `habitat`.
- Every existing call site passes the profile's current habitat so unrelated writes
  (cover pick, tag edit, folder rename, find create/edit, import) do not clobber it.

**Verify:** `npm run typecheck`.
**Done:** No call site omits `habitat`.

### Task 3 — Species detail UI + i18n

**Files:**
- `src/tabs/SpeciesTab.tsx`
- `src/i18n/index.ts`

**Action:**
- Add a `habitat` entry to the species detail tab strip next to `description`.
- Auto-growing textarea mirroring the description editor (same Forest Codex styling,
  save on blur), backed by `speciesHabitatInput` state reset on species change.
- All profile mutations in SpeciesTab send the current habitat draft.
- i18n keys `species.tabHabitat` and `edit.speciesHabitatPlaceholder` in hr + en.

**Verify:** `npm run typecheck`, `npm test -- SpeciesTab`.
**Done:** Habitat is editable and persists across species switches.

## Out of scope

- PDF/CSV export of habitat
- Habitat on individual finds (this is a species-level field)
