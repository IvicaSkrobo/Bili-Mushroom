# Quick Task 260821 — Unicode and species alias search

## Objective

Make Collection word-prefix search work for Croatian initial letters (`Č/Ć/Š/Ž/Đ`), make alphabetic Collection pagination use the same deterministic Croatian order as the frontend, and make Species search find scientific names, common names, synonyms, and other names without loading full profiles or issuing per-species queries. Preserve the current search UI and large-library pagination behavior.

## Existing contracts to preserve

- `get_collection_folders` must filter and order the complete grouped result before `LIMIT/OFFSET`; sorting an already-limited page in React is not a valid fix.
- Collection species search is a prefix-at-the-start-of-any-word search: `edu` finds `Boletus edulis`, while `dul` does not. `%` and `_` remain literal user input, and `*...*` display markup must not affect matching or ordering.
- `useSpeciesProfileSummaries` is the single lightweight batch read used by Species and Stats. Extend this contract with searchable alias arrays; do not replace it with `useSpeciesProfiles`, one `useSpeciesProfile` call per row, or any other N+1/full-profile load.
- `compareSpeciesNames` is the frontend ordering contract used across Collection, Species, Map, dialogs, and Stats. Backend alphabetic pagination must agree with it for Croatian letters and digraphs, not merely ASCII names.
- No visual redesign is needed. Keep the Forest Codex search field, virtualization, light/dark themes, and current empty/loading states unchanged.

## Task 1 — Register Unicode search and deterministic Croatian collation in SQLite

Ensure the in-memory test database uses the same registration helper so tests exercise production semantics.
- Add a deterministic Unicode normalization scalar for search: strip `*` display markup where the caller requests it and lowercase with Rust Unicode rules. Use it on the stored species expression in Collection filtering instead of SQLite `LOWER()`, whose case folding is ASCII-only. Keep the existing escaped pair of patterns (`query%` and `% query%`) so first/later word matching and literal `%`/`_` behavior remain unchanged.
- Add one app-owned Croatian species-name comparator/collation used by Collection SQL ordering. Give unrecognized Unicode characters a deterministic fallback and use the original name/id only as a stable tie-breaker.
- Replace `compareSpeciesNames`' platform-dependent `localeCompare` implementation with the matching deterministic TypeScript comparator so browser/Windows ICU differences cannot disagree with SQL page boundaries. Keep its public signature and all existing callers unchanged.
- Apply the Croatian collation in both alpha and recent-order secondary species sorting in `get_collection_folders_for_connection`. The full grouped result must still be ordered before pagination.
- Do not remove SQL pagination, collect the entire library in Rust, or fold Croatian letters to their ASCII bases; `Č` and `Ć` are distinct alphabet positions.

## Risks and safeguards

- SQLite user-defined functions/collations are per connection. Register them centrally in `open_db` and in the shared in-memory test setup; a helper registered only on the startup connection would fail on later IPC connections.
- A comparator that is not total/stable can duplicate or skip rows across `LIMIT/OFFSET`. Use the canonical Croatian weights plus deterministic fallback/tie-breakers, and test concatenated adjacent pages.
- JSON alias columns may be null or legacy-invalid. Decode to empty arrays exactly as full profiles do; one malformed optional alias field must not prevent the Species list from loading.
- No user data is written and no external input crosses a new trust boundary; LIKE wildcard escaping remains mandatory to prevent user input from unintentionally widening a search.

## Not in scope

- No Collection search by common name/synonym/other name; only Species gains alias discovery.
- No FTS table, schema migration, ICU extension, external dependency/service, or eager full-profile loading.
- No UI redesign, watcher, installer build, tag, or push.
