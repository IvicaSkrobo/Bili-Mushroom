# Quick Task 260820-tn3: Determinator + nalaznik fields on finds

## Goal

Record who actually found the mushroom, when it wasn't you. Optional free text,
present at every find-entry point and visible when you open the find. Mirrors the
`weather` field shipped in 260820-tca exactly.

## Tasks

### Task 1 — Persistence

**Files:** `src-tauri/migrations/0025_find_finder.sql` (new), `import.rs`, `finds.rs`

- `ALTER TABLE finds ADD COLUMN finder TEXT`; `version < 25` guard,
  `PRAGMA user_version = 25`, plus the idempotent repair block.
- `FindRecord.finder` at row index 17; append `, finder` to every find `SELECT`
  feeding `find_record_from_row`.
- `insert_find_row`, `CreateFindPayload`, `ImportPayload`, `UpdateFindPayload`
  (`update_find` UPDATE) all carry `finder`. Rust test fixtures get `finder: None`.

**Verify:** `cargo check --tests`.

### Task 2 — Entry points + display

**Files:** `src/lib/finds.ts`, `CreateFindDialog.tsx`, `EditFindDialog.tsx`,
`ImportDialog.tsx`, `PhotoLightbox.tsx`, `FindCard.tsx`, `exportCsv.ts`, `i18n/index.ts`

- Types: `Find`, `ImportPayload`, `UpdateFindPayload`, `CreateFindPayload`.
- Entry: CreateFindDialog (draft-persisted), EditFindDialog, ImportDialog shared
  header (`sharedFinder`), inline add/edit in PhotoLightbox.
- The lightbox's note, weather, and location saves must all pass
  `finder: find.finder ?? null` or they would wipe it.
- Display: lightbox metadata block (user icon), FindCard line when set,
  CSV `finder` column (update the header assertion in `exportCsv.test.ts`).
- i18n: `edit.finder`, `edit.finderPlaceholder`, `lightbox.finder`,
  `lightbox.noFinder`, `lightbox.addFinder`, `lightbox.editFinder` (hr + en).

**Verify:** `tsc --noEmit`, `vitest run`, app relaunch + live DB at user_version 25.

## Out of scope

- Filtering or grouping finds by finder.
- Any contacts/people registry — this is plain text, typed each time.
