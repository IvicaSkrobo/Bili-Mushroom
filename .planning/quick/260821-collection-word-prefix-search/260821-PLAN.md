# Quick Task 260821 — Collection word-prefix search

## Objective

Change the Collection species search from “beginning of the complete name” to “beginning of any word”, without restoring arbitrary substring matches. A query such as `b` must match `Boletus edulis`, `edu` must also match it, and `dul` must not. Preserve literal `%`/`_` handling, case-insensitive matching, `*` display-markup stripping, global alphabetical SQL ordering before pagination, and bounded result pages for large libraries.

## Existing contracts to preserve

- `push_find_search_filters` owns the SQL predicate and bound parameters for `FindSearchFilters.species_query`; keep filtering in SQLite rather than loading names and filtering in Rust/React.
- Stored species names may contain `*` presentation markup. Both search and alphabetical sort must continue comparing `LOWER(REPLACE(species_name, '*', ''))` (with existing trimming where appropriate).
- LIKE input must remain parameter-bound and escape user-provided `%` and `_` with `ESCAPE '\\'`; never interpolate the query into SQL.
- `get_collection_folders_for_connection` must continue applying `ORDER BY` to the complete filtered set before `LIMIT/OFFSET`. Do not move sorting or word matching to the frontend.

## Task — Implement and regression-test beginning-of-word matching

**Files:** `src-tauri/src/commands/import.rs`

**Action:**

- Replace the single whole-name-prefix predicate with two parameterized alternatives over one normalized species-name expression: `(normalized_name LIKE ? ESCAPE '\\' OR normalized_name LIKE ? ESCAPE '\\')`.
  - The first bound pattern is the escaped normalized query plus `%`, matching the first word.
  - The second is `% ` plus the escaped normalized query plus `%`, matching only immediately after a word-separating space. This deliberately permits a leading wildcard only for the second-word branch; it must not become the former unrestricted `%query%` substring search.
- Keep trimming/lowercasing query normalization and `*` stripping from stored names. Factor the pattern creation into a small helper returning both patterns if that keeps escaping single-sourced; blank/whitespace-only queries must still add no filter.
- Do not change location search semantics, `sort_mode`, page limits, grouping, representative-find hydration, or frontend debounce behavior.
- Update the existing collection prefix test into a word-prefix regression test. Its fixtures/assertions must prove all of these independently:
  - `b` finds `Boletus edulis` and a `*`-marked B name.
  - `edu` finds `Boletus edulis` through its second word.
  - `dul` returns no `Boletus edulis` result because it starts inside `edulis`.
  - matching is case-insensitive.
  - literal `%` and `_` in a query remain literals, not LIKE wildcards.
- Retain and run `collection_folder_alpha_sort_happens_before_pagination`; do not weaken its reverse-date fixture because it proves global alpha ordering happens before `LIMIT/OFFSET`.

**Verify:**

- Automated focused regression: `npm run test:rust -- collection_folder_species_search`
- Automated ordering guard: `npm run test:rust -- collection_folder_alpha_sort_happens_before_pagination`
- Full backend verification: `npm run test:rust`
- Static verification: `cargo check --all-targets --manifest-path src-tauri/Cargo.toml`

**Done:** Collection search responds from the first typed character and matches only the beginning of the full species name or a later word; arbitrary middle-of-word matches remain excluded, special characters remain safely literal, marked names remain searchable, and alphabetical pagination remains globally correct.

## Not in scope

- No fuzzy search, stemming, typo tolerance, or arbitrary substring matching.
- No frontend filtering or sorting of an already paginated page.
- No schema, index, debounce, page-size, Species-tab, location-search, or map-search changes.
