# Quick Task 260821 — Species find gallery and other names

## Objective

In the Species tab, make each row under **Finds** open that find's complete photo set in the existing `PhotoLightbox`, while keeping the paginated species query lean. In the **Description** profile editor, give **Other names** the same add/remove workflow already available for synonyms. Preserve the Forest Codex light/dark presentation, keyboard access, and large-library behavior.

## Existing contracts to reuse

- `useInfiniteSpeciesFinds(..., photosMode: 'primary')` intentionally supplies only the primary photo for each paginated row; do not change it to eagerly return all photos.
- `useFindPhotos(findId, enabled)` fetches the complete live photo list for one find and caches it under the existing finds query family.
- `PhotoLightbox` accepts `LightboxPhoto[]`, a `fallbackFind`, `currentIndex`, and `onIndexChange`; keep its existing keyboard arrows, buttons, metadata, edit action, and modal accessibility.
- `selectedProfile.other_names`, `species.otherNames`, and `species.otherNamesPlaceholder` already exist. Profile writes must continue sending every current field so adding an alternate name cannot erase synonyms, tags, status, cover, description, habitat, or fruiting-body override.

## Task 1 — Lazily open the clicked find's full photo gallery

**Files:** `src/tabs/SpeciesTab.tsx`, `src/tabs/SpeciesTab.test.tsx`

**Action:**

- Add `useFindPhotos` to the existing SpeciesTab hook imports and enable it only for the find selected from the **Finds** tab while its lightbox is open. Keep `useInfiniteSpeciesFinds` on primary-photo mode; loading every photo for every paginated find would regress large-library memory and IPC payloads.
- Separate the two lightbox intents already sharing state: the species/cover lightbox may continue browsing the bounded species window, while a click on a Finds row must build `LightboxPhoto[]` only from that find's live `useFindPhotos` result. Pair every returned `FindPhoto` with the clicked `Find`, updating its `photos` field to the live list so PhotoLightbox edit/metadata actions receive a consistent find snapshot.
- Open immediately with the row's already-loaded primary photo as a fallback, then replace it with the complete cached/fetched list without closing the dialog. Clamp/reset the index when the list changes, and clear the selected-find gallery state when the lightbox closes or the selected species changes so photos cannot leak between species/finds.
- A find with no photos must retain the current fallback behavior and must not invoke the photo query unnecessarily. Keep the existing 60-photo lightbox window only for the species-wide gallery; the selected find's own list should support normal previous/next navigation across all of its photos.
- Keep the row virtualized and the existing thumbnail lazy-loaded. Give the photo-opening button an accessible label that identifies the find/date and communicates that it opens its photos; do not introduce a parallel custom gallery or alter shared `PhotoLightbox` styling.

**Verify:**

- Extend the `useFindPhotos` mock with two non-primary photos for find `1`, and replace the null-only `PhotoLightbox` mock with a focused prop-observing mock.
- Regression test: switch to **Finds**, click the first photo row, assert the enabled query targets only find `1`, and assert PhotoLightbox receives all photos for find `1` in order with index `0` and no photo belonging to find `2`.
- Regression test the safe fallback for a find with zero photos (dialog receives the find fallback without an eager all-species payload).
- Automated: `npx vitest run src/tabs/SpeciesTab.test.tsx`

**Done:** Clicking a find in Species → Finds opens its own complete, navigable photo set; switching rows/species cannot show stale photos; initial species/find loading remains primary-only and paginated.

## Task 2 — Add and remove “Other names” beside synonyms

**Files:** `src/tabs/SpeciesTab.tsx`, `src/tabs/SpeciesTab.test.tsx`

**Action:**

- Add `otherNamesInput` state and reset it whenever the selected species changes, matching `synonymsInput` lifecycle.
- Add `handleAddOtherName` and `handleRemoveOtherName` alongside the synonym handlers. Trim values, reject blanks and exact duplicates, append/remove only `other_names`, and preserve the current synonyms and every other profile field in `useUpsertSpeciesProfile`.
- In the Description tab, render an **Other names** editor matching the restrained synonym control: localized label and placeholder, Enter/comma submission, plus button, removable chips, visible focus states, and accessible names on add/remove icon buttons. Reuse current Card/input/token classes so Herbarium Daybook and Nocturne Herbarium remain intact; do not modify shared UI primitives.
- Keep synonyms and other names visually distinct and independently editable. Adding/removing one must never rewrite the other list.

**Verify:**

- Seed the SpeciesTab profile fixture with one synonym and one other name.
- Regression test: switch to **Description**, enter another name through keyboard submission, and assert the profile mutation contains the appended `otherNames` plus the unchanged synonym and other profile fields.
- Regression test: remove an existing other name and assert only `otherNames` changes. Confirm blank/duplicate submission does not mutate.
- Assert the add/remove controls are discoverable by accessible role/name in both English-keyed test output and existing localized strings.
- Automated: `npx vitest run src/tabs/SpeciesTab.test.tsx`

**Done:** Description offers equivalent synonym and other-name workflows, both keyboard-operable, localized, theme-safe, and lossless to unrelated species metadata.
